# CasterlyGit

Applied AI developer tools and local-first systems built with explicit controls,
reviewable automation, and clear verification boundaries.

## Three engineering lanes

1. **Applied AI and developer tools** — bounded workflows for planning,
   retrieval, routing, and human review rather than opaque automation.
2. **Backend and platform** — typed state, service boundaries, offline-aware
   application behavior, and operational guardrails.
3. **Systems and local interaction** — local-first desktop and voice interfaces
   with platform-specific boundaries made explicit.

## Featured systems

The six pinned repositories are one engineering story, not a catalogue:

- **From intent to reviewed work:** [Cognitive Development OS](https://github.com/CasterlyGit/cognitive-development-os)
  structures typed intent and dry-run plans; [Trident](https://github.com/CasterlyGit/trident)
  keeps routing policy separate from correctness; [Shed](https://github.com/CasterlyGit/shed)
  retrieves local context with human-approved memory proposals; and
  [agent-harness](https://github.com/CasterlyGit/agent-harness) makes the
  ticket-to-pull-request workflow visible and reviewable.
- **From platform boundary to local interaction:** [emergency-ai](https://github.com/CasterlyGit/emergency-ai)
  explores an offline-first application and bounded service architecture, while
  [Curby](https://github.com/CasterlyGit/curby) explores macOS voice interaction
  and sandboxed task dispatch.
